# Gitignore Configuration

## Overview

This project uses a comprehensive, enterprise-level `.gitignore` configuration to ensure sensitive data, credentials, build artifacts, and environment-specific files are never committed to version control.

## Structure

The project has multiple `.gitignore` files at different levels:

1. **Root `.gitignore`** - Main configuration covering all projects
2. **`backend/.gitignore`** - Backend-specific rules
3. **`admin/.gitignore`** - Admin dashboard-specific rules
4. **`android/.gitignore`** - Android app-specific rules
5. **`mobile/ios/.gitignore`** - iOS app-specific rules (if exists)

## Critical Files That Are Ignored

### 🔴 NEVER COMMIT (High Security Risk)

#### Environment Variables & Secrets
- `.env` (all variants)
- `MASTER.env`
- `backend/services/gateway/.env`
- `admin/.env`
- Any file containing database credentials, API keys, or secrets

#### Signing Keys & Certificates
- `*.jks` (Java KeyStore)
- `*.keystore`
- `*.pem` (Private keys)
- `*.key` (Private keys)
- `*.crt` (Certificates)
- `*.p12`, `*.pfx` (Certificate bundles)

#### Cloud Credentials
- `.aws/` directory
- `aws-credentials.json`
- `gcloud-credentials.json`
- `service-account.json`

#### Android Signing
- `android/app/*.jks`
- `android/app/*.keystore`
- `android/keystore.properties`

### 🟡 Build Artifacts & Dependencies

- `node_modules/` (all locations)
- `build/`, `dist/`, `out/`
- `*.apk`, `*.aab` (Android builds)
- `.gradle/` (Gradle cache)
- `android/app/build/`
- `backend/shared/dist/`

### 🟢 Temporary & Cache Files

- `*.log` (all log files)
- `*.tmp`, `*.temp`
- `.cache/`
- `*.backup`, `*.sql.backup`
- Database scripts: `backend/database/scripts/*.js` (compiled from TypeScript)

## Files That ARE Committed

### ✅ Safe Template Files

- `.env.example` - Template with placeholder values
- `.env.template` - Template with placeholder values
- `backend/.env.example`
- `admin/.env.example`

### ✅ Source Code

- All `.ts`, `.tsx`, `.kt` (TypeScript, Kotlin source)
- All `.sql` migration files
- All `.md` documentation files
- Configuration files: `package.json`, `tsconfig.json`, `build.gradle.kts`

### ✅ Version Control

- `.gitignore` files
- `.gitkeep` placeholder files
- `README.md`, `SECURITY.md`

## Verification Commands

### Check for Sensitive Files in Git

```bash
# Check for .env files
git ls-files | grep -E "\.env$|\.env\."

# Check for keys and certificates
git ls-files | grep -E "\.(pem|key|crt|jks|keystore)$"

# Check for local properties
git ls-files | grep "local.properties"

# Check for log files
git ls-files | grep "\.log$"
```

### Test Gitignore Rules

```bash
# Test if specific files are ignored
git check-ignore -v backend/services/gateway/.env
git check-ignore -v android/local.properties
git check-ignore -v backend/database/scripts/test-api-response.js
```

### View Ignored Files

```bash
# Show all ignored files
git status --ignored

# Show only ignored files (short format)
git status --ignored --short | grep "^!!"
```

## Setup for New Developers

1. **Copy template files:**
   ```bash
   cp .env.example .env
   cp backend/.env.example backend/services/gateway/.env
   cp admin/.env.example admin/.env
   ```

2. **Fill in real credentials** (get from team lead or secrets manager)

3. **Verify gitignore is working:**
   ```bash
   git status
   # Should NOT show .env files
   ```

4. **Never commit sensitive files:**
   - Always review `git status` before committing
   - Use `git diff --cached` to review staged changes

## Emergency: Credentials Accidentally Committed

If credentials are accidentally committed:

1. **Rotate credentials immediately** (change passwords, regenerate API keys)
2. **Remove from git history:**
   ```bash
   # Using BFG Repo-Cleaner (recommended)
   bfg --delete-files .env
   
   # Or using git filter-branch
   git filter-branch --force --index-filter \
     "git rm --cached --ignore-unmatch backend/services/gateway/.env" \
     --prune-empty --tag-name-filter cat -- --all
   ```
3. **Force push** (coordinate with team):
   ```bash
   git push origin --force --all
   ```
4. **Notify security team** if applicable

## Maintenance

### Adding New Sensitive Files

When adding new sensitive file types, update:
1. Root `.gitignore`
2. Relevant subdirectory `.gitignore`
3. This documentation
4. `SECURITY.md`

### Regular Audits

Periodically run:
```bash
# Check for accidentally tracked sensitive files
git ls-files | grep -E "\.env|\.key|\.pem|\.jks|local\.properties"
```
